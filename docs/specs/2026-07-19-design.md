# endgame-canvas — Spike Design (2026-07-19)

## What this is

`endgame-canvas` is a localhost [tldraw](https://tldraw.dev) canvas exposed over MCP.
One core — a live tldraw canvas whose **editor is the source of truth** — driven and
read through three MCP primitives: **draw / read / export**. The same core serves two
modes with no code divergence:

- **Mode A — personal whiteboard.** The human draws in the browser UI; a single agent
  (Claude Code) draws back and reads what the human drew. A visual medium to align
  understanding before work — a self-hosted replacement for the Miro-collab loop.
- **Mode B — team diagram faculty.** Multiple endgame agents draw collaboratively (no
  human at the canvas), orchestrated turn-by-turn by a PM agent, then export raster
  images to attach into documents.

Architecturally A and B are identical: **MCP is symmetric to the number of clients.**
The only differences are who calls the tools, and whether the raster-read-of-human path
is exercised. This is why there is one tool, not two.

## Why a spike first

The only real technical risk lives in **Mode A's read path**: can an agent reliably read
a human's *freehand* strokes off the canvas? Everything else — agents drawing, structured
read, raster export — is low-risk and falls out of the same primitives. Prove the risky
bit before building the rest.

Freehand pen strokes are tldraw `draw` shapes stored as `props.segments[].points[]`
(vector polylines). Reading them *structurally* is possible but useless — a model can't
interpret raw point arrays. Freehand is only legible via the **raster** path
(screenshot → vision), exactly as cowart proved. Structured read is for the clean
shapes/text/arrows a party *places*; raster read is for freehand. They solve different
inputs; both exist, but only raster read carries risk — hence the spike targets it.

## Architecture (topology)

```
Claude Code (MCP client)
   │  stdio  (spike)   ── HTTP + turn-token deferred to Mode B
   ▼
Bun MCP server  ──cmd/resp over WS──►  WS relay (Bun.serve)  ◄──►  Browser: <Tldraw> editor
   (holds no state)         requestId-correlated                    (SOURCE OF TRUTH)
```

- The **browser tldraw editor is the source of truth** — not a server-side shadow model.
  This is the decisive choice: it is the only topology where a human's freehand strokes
  are readable, because every read round-trips to the live `editor`. (The rejected
  alternative — server owns an element map, browser renders it — cannot see anything the
  human draws.)
- The MCP server holds **no canvas state**. Every tool is a command the browser executes
  on the real `editor`, returning a response correlated by `requestId`.
- The WS relay routes each response to **its calling client only** — never broadcast.
  This is a transport-layer correctness requirement, independent of any PM-level write
  ordering. (Broadcast-to-all is the "echo storm" failure seen in reference
  implementations; PM serialization does not fix it because it lives one layer below.)

## Primitives (the whole product, eventually)

- **draw** — create / update / delete shapes on the canvas
- **read** — structured (`editor.getCurrentPageShapes()`) + raster (`editor.toImageDataUrl({ bounds })`)
- **export** — raster to a file path for document embedding (Mode B)

## Spike scope (v0)

Three tools only:

| tool | does | role |
|---|---|---|
| `read_canvas` | browser `editor.toImageDataUrl({ bounds })` → MCP image content | **under test** |
| `get_snapshot` | `getCurrentPageShapes()` → structured summary | cheap, included |
| `create_shape` | geo + text | proves the draw-back loop (not a kill gate) |

Browser: bare `<Tldraw persistenceKey="endgame-canvas">` + WS client. No auth, single tab.

**Deferred** (do not build until the kill criterion passes): connect / flowchart / frame,
export-to-file, HTTP transport + turn-token, multi-agent orchestration, per-agent
attribution colours, structured-read enrichment.

## Kill criterion — time-box: 1 day

The human draws three annotations on the canvas:

1. a freehand text scribble
2. a freehand circle enclosing one shape
3. an arrow from a note pointing at a target shape

The agent calls `read_canvas` and must correctly report all three: read the scribbled
text, name *which* shape the circle encloses, and name *what* the arrow points at.

- **Pass** → topology works; invest in the rest (structured-read enrichment, draw
  vocabulary, Mode B). 
- **Fail** (cannot resolve the spatial references) → kill the tldraw-read approach. No
  7-day build spent.

## Stack

- **Bun** — runtime, package manager, test runner. The MCP server runs as `bun server.ts`
  with **no build step**. The WS relay uses native `Bun.serve({ websocket })`, dropping
  the `ws` dependency.
- **tldraw** + React, bundled by **Vite** for the browser app (`bun run dev`).
- **@modelcontextprotocol/sdk** — the stdio MCP server.
- Registered with: `claude mcp add endgame-canvas -- bun /abs/path/server.ts`
