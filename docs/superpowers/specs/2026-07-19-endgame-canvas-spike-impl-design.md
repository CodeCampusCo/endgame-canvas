# endgame-canvas — Spike Implementation Design (2026-07-19)

Implementation-level design for the v0 spike. Builds on and does not replace
`docs/specs/2026-07-19-design.md` (the product spike design + kill criterion). This doc
resolves the *how*: process topology, wire protocol, project layout, and the exact editor
calls each tool makes.

Scope is unchanged: **three tools** (`read_canvas`, `get_snapshot`, `create_shape`),
single browser tab, single agent, stdio MCP. Everything the parent spec marks *deferred*
stays deferred.

## Topology — relay as a standalone hub (approach B)

Three processes:

```
Terminal 1:  bun run dev        # Vite, serves the browser app (browser/)
Terminal 2:  bun relay.ts       # WS hub, long-lived — the durable core
Claude Code ──spawn──► bun server.ts    # stdio MCP + WS client → relay

Browser tab ───────────(WS client, role=browser)──►  relay :9910
server.ts   ───────────(WS client, role=mcp)─────►  relay :9910
```

Rationale (decided with the user): the relay is a **persistent hub**; both the browser and
each MCP server attach to it as WS **clients**. The MCP server never hosts a socket server
itself. This decouples the browser's lifecycle from the MCP process — restarting or adding
agents never disturbs the canvas — and it is the exact shape Mode B needs later (many
`server.ts` clients, one relay, one browser). The browser tldraw editor remains the source
of truth in every mode; the relay holds no canvas state, only live socket references.

The relay distinguishes connections by a `role` query param on connect
(`?role=browser` / `?role=mcp`). For the spike it keeps **one** browser socket reference;
a second browser connection replaces it (single-tab assumption, logged).

## Wire protocol

One request/response shape over WS, JSON:

```
req:   { requestId, tool, params }
resp:  { requestId, ok: true,  result }
     | { requestId, ok: false, error }
```

- `requestId` — generated by `server.ts` per tool call (e.g. `crypto.randomUUID()`).
- Relay routing (never broadcast):
  - a `req` from an mcp client → forwarded to the browser socket; relay records
    `requestId → originating mcp socket`.
  - a `resp` from the browser → looked up by `requestId` → sent **only** to the mcp
    socket that owns it, then the mapping is dropped.
- This is the transport-layer "route to caller only" requirement. It is trivial with one
  agent but is written correctly now so Mode B inherits it for free.

### Why the browser must respond

The MCP server holds no state, so the browser's response **is the data** — not an ack:
`read_canvas` returns the rendered image, `get_snapshot` returns the shape list (both exist
only in the live editor), and `create_shape` returns the new shape `id` plus success/error
so the agent can confirm the write and reference the shape later. The MCP protocol is
request→response, so every tool call must resolve with a value; `requestId` is what pairs
each response back to the caller that is awaiting it.

## Failure handling

`server.ts` awaits a Promise per `requestId`. Two guards prevent it from hanging forever:

- **No browser connected** — relay replies immediately with
  `{ ok: false, error: "no browser connected — open the canvas tab" }`. The server does not
  wait.
- **Browser connected but silent** — server-side timeout of **10 s** rejects the Promise
  with `error: "canvas timeout"`. The `requestId` mapping in the relay is cleaned up on
  timeout so it does not leak.

Both surface to the agent as a normal tool error, never a hung call.

## Project layout

Single package, no build step on the server side:

```
endgame-canvas/
├── server.ts            # stdio MCP (@modelcontextprotocol/sdk) + WS client → relay
├── relay.ts             # Bun.serve({ websocket }) hub, role-aware routing
├── package.json         # deps + scripts
├── browser/             # Vite + React + tldraw app
│   ├── index.html
│   ├── vite.config.ts
│   └── src/
│       └── main.tsx     # <Tldraw persistenceKey> + onMount → WS client → runs tools on editor
└── docs/specs/...
```

Scripts (`package.json`):
- `relay`  → `bun relay.ts`
- `server` → `bun server.ts`  (also the command registered with `claude mcp add`)
- `dev`    → vite dev server for `browser/`

Ports (hardcoded for the spike): relay WS `9910`, Vite `5173`.

Dependencies: `tldraw`, `react`, `react-dom`, `@modelcontextprotocol/sdk`, `vite`,
`@vitejs/plugin-react`. WS uses native `Bun.serve` (relay) and the browser's native
`WebSocket` — no `ws` dependency.

## Browser wiring

```tsx
import { Tldraw } from 'tldraw'
import 'tldraw/tldraw.css'

<Tldraw persistenceKey="endgame-canvas" onMount={(editor) => connect(editor)} />
```

`connect(editor)` opens `ws://localhost:9910/?role=browser`, and on each `req` message
dispatches by `tool`, runs the matching editor call, and posts back
`{ requestId, ok, result }`. It auto-reconnects on close (1 s backoff) so a relay or server
restart self-heals without touching the canvas (state is in `persistenceKey` storage).

## The three tools — exact editor calls

### `read_canvas` — the one under test

Browser side:
```
const bounds = editor.getCurrentPageBounds()          // tight box around all shapes
// return { empty: true } if no shapes on the page
const dataUrl = await editor.toImageDataUrl({ bounds, padding, background })
```
Server converts the returned data URL into MCP **image content** so the agent sees the
whole canvas at once — required to resolve all three kill-criterion annotations (scribbled
text, which shape a circle encloses, what an arrow points at).

Exact `toImageDataUrl` options (format/scale/padding/background) are confirmed against
current tldraw docs (context7) during implementation; the bounds decision — crop to
`getCurrentPageBounds()`, not the viewport — is fixed here so no shape can fall outside the
frame.

### `get_snapshot` — cheap structured read

```
const shapes = editor.getCurrentPageShapes()
// → summarize: id, type, x, y, w/h, and plain text extracted from props.richText
```
Returns a compact JSON list. **Note:** text lives in `props.richText` (a rich-text object)
in current tldraw, not a plain `props.text` field — extract plain text from it. Freehand
`draw` shapes are reported as `type: "draw"` with a point count only; they are *not*
interpretable structurally (that is the whole reason `read_canvas` exists).

### `create_shape` — proves the draw-back loop (not a kill gate)

Signature:
```
create_shape({ type: "rectangle" | "ellipse" | "text", x, y, text? }) → { id }
```
Maps to tldraw:
- `"text"` → `editor.createShape({ type: 'text', x, y, props: { richText: toRichText(text) } })`
- `"rectangle" | "ellipse"` → `editor.createShape({ type: 'geo', x, y, props: { geo: <type>, richText: toRichText(text ?? '') } })`

Uses `toRichText()` for any label. Returns the created shape `id`. Arrow / connect / frame
stay deferred per the parent spec.

## Registration & the kill test

1. `bun run dev` (Vite) and `bun relay.ts` (relay) running; open the canvas tab.
2. `claude mcp add endgame-canvas -- bun /abs/path/server.ts`, restart so the tools load.
3. Human draws the three annotations; agent calls `read_canvas` and must report all three.
   Pass → build the rest; fail → kill the tldraw-read approach.

## Non-goals (unchanged from parent spec)

connect / flowchart / frame, export-to-file, HTTP transport + turn-token, multi-agent
orchestration, per-agent attribution colours, structured-read enrichment. Do not build
these until the kill criterion passes.
